# BusForge 架构与类说明

> 本文档为项目内实时维护文档：新增/修改类或方法时，必须同步更新本文对应条目。
> 所有代码注释与本文档均使用中文，禁止乱码。

## 一、总体分层

```
设备连接层  app/devices/drivers/*    硬件DLL绑定与单通道驱动
设备管理    app/devices/*            设备池/软件通道/连接实例/异步连接/设备面板与弹窗
数据中台    app/datahub/data_hub.py  轮询收数/解码/按订阅推送
解析层      app/protocol/*           DBC解析与信号编解码
数据模型    app/models/*             DBC模型/帧与信号DTO/报文/信号定义
公共基础    app/common/*             i18n/全局UI状态/工作空间/变量系统/消息总线
报文记录    app/recorder/*           Logger 记录引擎与记录面板
监控面板    app/monitors/*           Trace/信号监控/图形曲线 (纯展示)
仿真发送    app/transmit/*           统一发送面板与数据库报文选择弹窗
诊断        app/diagnostic/*         UDS诊断面板与UDS客户端
脚本        app/script/*             类CAPL脚本引擎/运行时/编辑器
展示框架    app/ui/*                 主窗口/工具栏/工程树/ADS停靠/全局配置/自定义面板
```

数据流向：硬件 -> 设备驱动 -> DataHub轮询 -> 解析层解码 -> 按订阅合批推送 -> 展示面板。
控制流向：设备管理面板/项目树 -> DeviceManager(连接) / DataHub(运行)。

## 二、设备连接层 (app/devices/drivers)

### base.py — BaseBusDevice / BusState / BusStats
- `BaseBusDevice`：所有总线设备的抽象基类，定义 open/close/start/stop/send/receive/receive_batch/on_receive 接口与统计计数。
- `BusState`：设备状态枚举（DISCONNECTED/CONNECTED/RUNNING/ERROR）。
- `BusStats`：收发统计（tx_count/rx_count/error_count/bus_load/最后收发时间）。

### ts_jna.py — TsMasterLib / find_tsmaster_dll
- `find_tsmaster_dll()`：按 环境变量->注册表->默认路径 顺序查找 tsMaster.dll。
- `TsMasterLib`：DLL ctypes 绑定封装。方法：
  - `initialize/finalize`：库初始化与释放。
  - `connect/disconnect`：tsapp_connect / tsapp_disconnect。
  - `enumerate_hw_devices/get_hw_info_by_index`：设备枚举与硬件信息。
  - `configure_baudrate_can/configure_baudrate_canfd/configure_baudrate_lin`：波特率配置（含只听、终端电阻参数）。
  - `set_can_channel_count/set_lin_channel_count`：应用通道计数下发。
  - `set_mapping_verbose`：应用通道<->硬件通道映射设置（移植自Java同名接口）。
  - `start_lin_channel/stop_lin_channel`：LIN通道启停。
  - `transmit_can_async/transmit_canfd_async`：异步发送。
  - `enable_receive_fifo/clear_can_receive_buffers/receive_can_msgs/receive_canfd_msgs`：FIFO接收。
  - `get_error_description`：DLL错误码文本化。

### ts_service.py — TsMasterService / ChannelMapping / 常量表
移植自 Java `tosuncan/TSMasterServiceImpl` 的设备连接核心（仅连接逻辑），优化为数据驱动：
- 常量：`AppChannelType`(CAN/LIN/FlexRay)、`BusToolDeviceType`(TS_USB_DEVICE)、`TSDeviceSubType`(TC1013/1016/1026/1034)。
- `MODEL_CHANNEL_LAYOUT`：型号通道布局表，替代Java逐型号硬编码映射函数。
- `ChannelMapping`：映射记录（应用类型/应用通道号/型号/设备索引/序列号/硬件通道）。
- `TsMasterService`（全局单例+线程锁）方法：
  - `initialize/finalize`：库生命周期。
  - `enumerate_devices/get_device_count`：设备枚举。
  - `start(device_name, device_index, serial)`：启动设备=断连->初始化->autoMapping->恢复连接（对应Java start）。
  - `_auto_mapping`：统计启用设备总通道数->下发通道计数->按布局表建立映射（对应Java autoMapping）。
  - `connect/disconnect`：应用连接与断开（connected属性查询）。
  - `get_app_channel(device_index, hw_channel, type)`：硬件通道->应用通道号查询（对应Java getTsDeviceChannelMapping）。
  - `get_channel_count_by_model`：型号通道数查询。
  - `set_can_baudrate/set_canfd_baudrate`：按映射通道配置波特率，内部执行 断连-配置-重连（对应Java setCanBaudrate/setCanFDBaudrate）。
  - `set_channel_enabled`：通道使能（对应Java setChannelEnabled）。
  - `clear_buffer`：清接收缓存。
  - `start_lin_channel/stop_lin_channel`：LIN通道配置与启停。

### ts_master.py — TsMasterCanDevice
单硬件通道驱动（一个实例=设备+硬件通道）：
- `__init__(channel, device_index, dll_path, device_model, serial, listen_only, terminal_resistor)`：保存通道参数。
- `app_channel`：映射后DLL应用通道号（多设备共享连接不错位）。
- `open()`：服务start设备->connect->按参数配置波特率(FD配置仲裁+数据域)。
- `close()/start()/stop()`：通道生命周期；start清接收缓存。
- `send()/receive()/receive_batch()`：经映射通道号收发；只听模式禁止发送。

### ts_structures.py
- TSMaster DLL 交互所需的 ctypes 结构体与常量定义（供 ts_jna/ts_service 使用）。

### zlg_lib.py — ZlgLib / 结构体 / 常量表
移植自 Java ZlgCanLib/ZlgApi/ZlgCanPropertyManager/ZlgCanConstants（仅连接底层）：
- 常量：STATUS_OK/ERR、SEND_ECHO/SEND_BRS、CAN_EFF_FLAG、ZLG_DEVICE_TYPES(型号->设备类型)、model_to_device_type()。
- 结构体：ZCANCan/ZCANCanFd/ZCANChannelInitConfig/ZCANCanFrame/ZCANCanFdFrame/ZCANTransmitData/ZCANTransmitFDData/ZCANReceiveData/ZCANReceiveFDData/ZCANDeviceInfo/ZCANIProperty(属性函数指针)。
- `ZlgLib` 方法：open_device/close_device/get_device_info/is_device_online/get_iproperty/release_iproperty/set_property(通道/属性名)、init_can/start_can/reset_can/clear_buffer/transmit/transmit_fd/receive/receive_fd；make_can_id/parse_can_id 帧ID标志位处理。

### zlg.py — ZlgCanDevice
周立功单通道驱动（移植自Java ZlgCan连接流程并优化）：
- 共享设备句柄：类级 _shared_devices 引用计数，同设备多通道只开一次。
- `open()`：开设备->属性配置(canfd_standard/abit/dbit波特率, InitCAN前)->InitCAN(canType=1, 只听模式)->滤波配置(清/标准/扩展/生效)->终端电阻->StartCAN。
- `start()/stop()/close()`：清缓冲/ResetCAN/释放共享句柄。
- `send()/receive()/receive_batch()`：经通道句柄收发，CAN/CAN FD，只听禁发。

### vector.py — VectorCanDevice
- 移植说明：Java侧VectorCanFDX依赖CANoe FDX TCP；py侧优化为经 python-can 的 vector 接口直连XL驱动(vxlapi64.dll)，无需CANoe。
- `open()`：can.Bus(interface='vector', app_name, channel, bitrate, fd, data_bitrate, serial)；`close()`：bus.shutdown()。
- `send()/receive()/receive_batch()`：python-can Message 与统一帧dict互转。

### virtual.py
- `VirtualBusDevice`：虚拟环回总线（无硬件开发/测试用），支持 inject_frame 注入。

## 三、设备管理 (app/devices)

### device_manager.py — DeviceInfo / SoftwareChannel / DeviceManager
- `DeviceInfo`：硬件设备元数据（device_id工程内唯一/vendor/model/serial/index/bus_type/vendor_params/state）。
- `SoftwareChannel`：软件通道（key工程内唯一/device_id/hw_channel/bus_type/baud_rate/is_fd/data_baud_rate/dbc_path/enabled/listen_only/terminal_resistor），`to_dict()` 持久化。

#### DeviceManager（单例，QObject，按工程分区持有设备池）
- 归属模型：设备/通道“定义”归属工程（project_id）；`_pools[pid]={'devices','channels'}` + `_active_project` 指针；`_devices/_channels` 属性解析到活动工程池（无活动工程时读返回空、写被拒绝）。同一物理设备可在多工程各自定义不同映射；通道 key 工程内唯一。
- 线程安全：`_lock`(RLock) 保护连接/断开与池结构变更；读方法不加锁（依赖GIL原子性，避免异步连接时阻塞UI绘制）。
- 信号：`device_state_changed(device_id, state)`、`channel_state_changed(key, state)`、`pool_changed()`。
- 工程池生命周期：`register_project(pid,name)/unregister_project(pid)/set_active_project(pid,name)`（切换前先断开旧工程全部连接）/`set_project_name(pid,name)`/`active_project`/`active_project_name`（供设备面板显示当前工程名）。
- 设备池（作用域=活动工程）：`add_device/remove_device`（移除设备时其绑定通道解绑为未绑定，不删通道）`/update_device_params/get_device/list_devices`。
- 软件通道（工程内唯一，可未绑定设备）：`suggest_channel_key/assign_channel`（device_id 为空=未绑定）`/bind_channel`（绑定设备硬件通道）`/channel_bound/rename_channel/update_channel/remove_channel/get_channel/list_channels/channels_of_device/channel_state`。连接未绑定通道会被拒绝并提示先去设备管理绑定。
- 连接（通道级原子，设备级循环；仅开硬件不收数）：
  - `connect_channel(key)/disconnect_channel(key)`、`connect_device(id)/disconnect_device(id)`、`connect_channels(keys)`（顺序批量，供异步worker/同步运行）、`disconnect_all_active()`（断开活动工程全部连接）。
  - `ensure_connected(id)/is_connected(id)`、`get_instance(key)/connected_instances()`、`send(channel_key, ...)`（连接即可发）、`_release_tsmaster_if_idle()`。
- 运行占有：`set_acquired(ids, bool)/is_acquired(id)`（运行中项目蓝色标记）。
- 持久化（按工程）：`export_project(pid)`（导出完整定义存.bfproj）/`import_project(pid, data)`（填充工程池，不切活动/不碰硬件）；`shutdown()` 退出断开全部连接。
- 说明：连接态字典用普通 channel_key 作键——因“切换工程即断开旧工程”，任一时刻仅活动工程通道处于连接态，无跨工程同名冲突。已移除空闲倒计时回收（改为运行/停止/切换驱动连接生命周期）。

### connect_worker.py — ConnectWorker（QThread）
- 运行工程时的异步连接线程：工作线程内顺序 `dm.connect_channel`，逐条 `progress(done,total,key)`，支持 `cancel()`，完成 `finished_ok(ok,err)`；只连接不碰QTimer（轮询定时器由主线程 begin_polling 启动）。

### device_dialog.py — DeviceSelectDialog / ChannelParamDialog
- `DeviceSelectDialog`：枚举硬件(TSMaster DLL/ZLG 探测; Vector/Virtual 提供默认行)，仅允许从列表选中添加，未选中时 OK 被拦截。
- `ChannelParamDialog`：设备参数配置(波特率/CAN FD/数据波特率/只听/终端电阻)，FD 关闭时数据波特率以灰底占位标签替换显示(Windows原生风格不绘制QComboBox disabled背景)；设备绑定、硬件通道、DBC 均改在通道表或工程树内设置，故弹窗不再含此三者(避免重复)；取代原 ChannelBindDialog/ChannelAdvancedDialog。

### device_manage_panel.py — DeviceManagePanel（当前工程设备管理面板，ADS单实例dock）
- 职责：管理当前工程的物理设备 + 将工程树创建的软件通道绑定到设备硬件通道。作用域=活动工程，随切换 `reload_all`；标题显示当前工程名(`设备池 (工程: X)`)；无设备显示空态提示。
- 两栏布局(连接由“运行工程”自动完成，已移除设备参数表单/手动连接/统计)：左=设备列表(分组+状态灯；设备以 型号·序列号 区分；右键/【添加设备】枚举硬件) / 右=软件通道表。
- 添加设备：`_on_add_device/_on_dev_tree_menu/_populate_add_device_menu/_create_device`（枚举式；CAN=TSMaster/Vector/ZLG/Virtual，LIN=TSMaster；仅加设备不自动建通道）；`_remove_device_by_id`（移除设备时提示其绑定通道将解绑）。
- 通道绑定(表内直接编辑)：“设备”列下拉(`_on_inline_device`→`bind_channel`)与“硬件通道”列 SpinBox(`_on_inline_hw`→`update_channel`)即选即绑；连接中禁用。二者不再放进弹窗(避免与表列重复)。
- 通道表(5列)：软件通道(只读)/设备(下拉绑定)/硬件通道(SpinBox)/参数配置(行内【设备参数配置】按钮)/状态(只读)；名称/设备列 Stretch、其余按内容自适应(无横向滚动条)。
- 行内【设备参数配置】按钮(`_on_channel_param`)→`ChannelParamDialog` 配置波特率/FD/数据波特率/只听/终端电阻(`update_channel`)。无底部按钮行；连接由“运行工程”自动完成，无手动连接按钮。

## 四、数据中台 (app/datahub/data_hub.py)

### 订阅类型常量
`KIND_FRAME/KIND_MESSAGE/KIND_SIGNAL/KIND_STATS`。

### Subscription
订阅句柄：subscriber_id、kinds、channels(None=全部)、filter(message_ids/signal_names)；`matches_channel/matches_message_id/matches_signal`。

### DataHub（全局单例，QObject）
- 信号：`push(subscriber_id, kind, payload列表)`、`running_changed(bool)`、`dbc_changed(channel_key, dbc)`。
- 订阅：`register/unregister/update_subscription/get_subscription`；创建监控界面即注册、关闭即注销。
- 解析层持有：`set_channel_dbc/get_dbc/get_codec/load_channel_dbc_file`（UI禁止自建codec）。
- 运行控制：`begin_polling(channel_keys)`（假定已连接→占有标记+启动轮询）、`stop_polling()`（停轮询清占有，不断开）、`start_project/stop_project`（同步包装=连接+轮询 / 停轮询+断开，供脚本）、`running`属性。
- 通道暂停：`set_channel_paused(key, bool)`（UDS同步收发避免抢帧）。
- 内部：`_poll`(10ms轮询已连接通道)、`_ingest`(按需解码+分发)、`_flush_push`(30ms合批推送)、`_on_device_state/_on_channel_state`(状态转发)。
- 缓存查询：`get_signal_cache/get_last_messages/get_stats`。

## 五、解析层与数据模型 (app/protocol / app/models)

### protocol/dbc_parser.py — DbcParser
- DBC 文件解析器：产出 `DbcDatabase` 模型（报文/信号/值描述/发送节点）。

### protocol/can_codec.py — CanCodec
- 信号编解码器：按 DBC 模型对帧 payload 解码（帧->信号值）与编码（信号值->帧），供 DataHub 与发送面板统一调用。

### models/dbc_model.py / signal.py / message.py
- `DbcDatabase/DbcMessage` 等 DBC 内存模型；`Signal/ByteOrder` 信号定义与字节序；`CanMessage` 报文数据结构。

### models/dto.py — 推送数据结构
- `SignalValueDTO`：信号值（name/message_name/channel_key/phys/raw/unit/value_desc/timestamp）。
- `FrameDTO`：总线帧（含解码名与信号列表、data_hex/data_length/id_hex 属性）。
- `StatsDTO`：通道统计快照。
- `DeviceStateDTO`：设备/通道状态事件。

## 六、公共基础 (app/common)

### i18n.py — tr()
- 中英文国际化（词典式，以中文原文为 key）：`tr("新建工程")` 在 en_US 下返回 "New Project"，zh_CN 或未命中时原样返回；支持 `{占位符}`。语言状态由 UISettings 持有，组件订阅 `language_changed` 调 `retranslateUi()` 实时切换。

### ui_settings.py — UISettings（全局单例，QObject）
- 全局 UI 显示状态：语言(zh_CN/en_US)与数值进制(hex/dec)；变更发信号，状态持久化委托给 bind 的 AppConfig（变更即写回并落盘）。
- 格式化助手 `fmt_id/fmt_data/fmt_int` 供各数据视图统一调用。

### workspace.py — WorkspaceManager
- 工作空间/工程自动持久化（路径感知）：工程在“创建/更改/删除”时即刻落盘为独立 `.bfproj`；删除工程即删除文件；`workspace.json` 会话索引记录打开的工程与活动工程供启动恢复。
- 保存目录由 `AppConfig.save_dir` 配置；为空时默认 = 运行/安装路径 `data/`（`APP_RUN_DIR=data 的父级`，即工程根下 data 目录）。

### variable_system.py — VariableRegistry / AppVariable / VarType
- 全局变量系统：Panel 控件与 Script 脚本共享的变量注册表；观察者模式（值变化通知）实现 Panel<->Script 双向绑定。

### message_bus.py — MessageBus（全局单例，QObject）
- 内部消息总线（仅控制信令）：面板创建/关闭请求、变量变化转发；帧数据/DBC/统计不经由此总线，统一由 DataHub 按订阅推送。

## 七、报文记录 (app/recorder)

### can_logger.py — CanLogger / AutoLogger
- `CanLogger`（全局单例）：订阅中台帧流保存为 ASC/BLF（基于 python-can 的 ASCWriter/BLFWriter）；负责“启动->逐帧写入(超上限轮转)->停止落盘”链路。
- 大小轮转：每 128 帧检查文件大小，超过 `AppConfig.logger_max_size_mb`(50MB~1GB) 自动开新文件（`时间戳_序号.ext`）。
- 过滤：写盘前 `_accept()` 判定（通道勾选/报文ID/TX-RX 方向）；0 帧停止时删除占位文件并 `notice` 提示。
- `AutoLogger`（单例）：监听 `DataHub.running_changed`，`AppConfig.logger_auto_start` 开启且未录制时随工程运行自动 `start(default_log_path())`。
- 全局配置存 `AppConfig.logger_*`；默认路径 `logger_root()/项目名/日期/时间戳.ext`。

### logger_panel.py — LoggerPanel
- 独立报文记录面板（与 Trace 平级，各自独立订阅中台）：存储位置+全局配置快捷 -> 格式/路径 -> 开始/停止 -> 跟随项目运行自动记录 -> 项目日志文件预览（可导出/删除）。

## 八、监控面板 (app/monitors，纯展示)

### trace_view.py — TraceView
- 订阅 kinds={frame, stats}；通道下拉=重新订阅；push槽只写表格与统计栏；显示过滤仅隐藏行。
- 列头漏斗筛选（CANoe 式，`_TraceHeaderView` 自绘）；分支加/减号指示符由 `_BranchIndicatorStyle` 矢量代理样式绘制（高DPI清晰，替代原 QSS 位图）。

### signal_monitor.py — SignalMonitorPanel
- 信号树元数据来源 DataHub.get_dbc；勾选=register/update filter.signal_names；push槽只缓存DTO；100ms定时写表格；双击注册全局变量。

### graphy_view.py — GraphyView
- 订阅 kinds={signal}；勾选信号建曲线；push槽只追加缓冲；100ms重绘。

## 九、仿真发送 (app/transmit)

### transmit_panel.py — TransmitPanel
- 统一仿真发送面板（参照 zxdoc），取代原 IG(手动发送) 与 Generator(报文序列)：作为 Monitor 下的独立面板，每行自带【通道】列。
- 布局：工具栏(启动/停止全部 | 添加 CAN/CAN FD/数据库帧 | 删除 | 上移/下移) + 发送列表(树表, 支持“序列”嵌套成员帧; 列: 触发/启用/名称/通道/ID/类型/长度/次数/周期) + 信号/原始数据场(随选中行联动)。
- 次数=0 表示周期发送，否则按次数+间隔发送；序列行触发后按间隔顺序发送成员帧。
- 发送走 DeviceManager（异步 `send_async`，失败经 `send_failed` 信号由 `_on_dm_send_failed` 槽处理）；数据库帧编码走 DataHub 解析层 CanCodec；全部文本经 tr() 实时切换语言。

### db_message_dialog.py — DbMessagePickerDialog

## 十三、运行语义与关键约束

1. 职责分离：软件通道=工程逻辑总线(工程树 CAN/LIN 下添加，可先未绑定)；物理设备=硬件(设备管理面板枚举添加)；绑定=通道↔设备硬件通道(设备管理)。设备/通道定义随工程私有并存于 `.bfproj`；同一物理设备可在多工程各自映射；通道 key 工程内唯一。未绑定通道无法连接/运行，UI 明确提示先去设备管理绑定。
2. 连接生命周期=运行生命周期：运行工程=异步连接本工程启用通道(进度反馈,不冻结UI)→开始收数推送；终止/切换工程=停收数推送+断开本工程全部连接。
3. 单运行项目制：运行B自动终止A；项目切换先停运行再换活动工程池(切换即断开旧工程连接)。
4. 应用启动零硬件：不再恢复全局设备池；工程定义仅在导入 `.bfproj` 时惰性加载。
5. 展示层零解码：解码统一在DataHub内经解析层完成。
6. 发送异步化：UI 线程调用 `DeviceManager.send_async()` 仅入队不阻塞（ZLG 无 ACK 时驱动阻塞约1.5s，同步调用会卡死界面）；新增异步信号必须同步实现对应槽函数。
7. 记录独立性：Logger 与 Trace 平级各自订阅中台，互不依赖；Logger 默认不随 Trace 启动，由自身开关/`logger_auto_start` 控制。
